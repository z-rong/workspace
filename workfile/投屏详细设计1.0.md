## 1 需求背景
### 1.1 应用需求
应用开启自启动投屏接收端服务，等待投屏端；
### 1.2 业务流程
#### 1.2.1 主动投屏流程
##### 业务流程

1. 应用开机自动启动服务。
2. 应用调用setSurfaces接口，将显示用的窗口surface设置给投屏服务。
3. 应用调用start接口，启动被投端接收服务，等待主投端发起投屏。
4. 主投端开启投屏设备发现，并选择对应的被投端设备，发起投屏请求。
5. 投屏服务接受投屏请求，并进行wfd协议交互。
6. 投屏服务与主投端协议交换完成后，通知应用设备已经接入。
7. 投票服务选择空余surface绑定到连接上来的设备，接收主投端发送过来的视频流并解码输出到选择的surface上。

## 2 框架模型结构
![](https://cdn.nlark.com/yuque/0/2023/jpeg/32611479/1677842754127-011d0eeb-83cc-4763-8e22-39a6b689329f.jpeg)

1. 一个context与可以包含多个sinkagent和srcagent，一个srcagent一定归属于一个sinkagent。
2. 一个sinkagent对应一个consumer，一个srcagent对应一个producer。
3. 一个mediachannel只包含一个consumer，但包含多个producer。
4. 一个mediachannel对应一个环形队列，环形队列用于缓存consumer提供的编码后的媒体数据，此mediachannel中的produer以被动模式注册到此环形队列，当被通知有数据进入环形队列时，去队列取数据进行网络发送。
5. 一个mediachannel对应一个playcontroller，此播放器以被动模式从环形队列获取音视频编码数据，封装了audioplayer和videoplayer。audioplayer用于将音频数据解码成pcm并进行音频播放；videoplayer主要通过avcodec将视频编码数据解码成yuv并直接进行送显，显示用的surface由外部应用调用接口来设定。

## 3 框架接口流程
### 3.1 设置显示Surface列表（必须在startWfdSink前设置）
#### 业务流程

1. 应用侧通过IPC向框架层发送设置Surface列表的消息（同步消息）。
2. wfd scene 收到此列表后，判断Surface列表总数和前台显示数是否超过限制，总数或者前台显示数超过限制直接返回错误。
3. 数量符合要求，则由scene 存储在map中，key就是 GetUniqueId  获取到的surfaceId，默认投屏质量为1920*1080 30帧。

### 3.2 设置投屏视频格式setVideoFormat
#### 业务流程

1. 应用侧通过IPC向框架层发送设置视频格式（同步消息）。
2. 设置类型为：640*480 25帧，640*480 30帧，1280*720 25帧，1280*720 30帧，1920*1080 25帧，1920*1080 30帧（默认）。
3. wfd scene根据surfaceId查找对应的surface，如果surfaceId为0，则更新所有的surface投屏质量，在下次使用此surface时，设置才生效。

### 3.3 开启wfd sink端服务并接收source端投屏
#### 业务流程

1. 应用侧通过IPC连接上框架，触发wfd scene创建并初始化WifiP2p相关模块（初始化操作和开启操作分开）。
2. 应用侧通过IPC向框架层发送WfdSinkStart，wfd scene接收到以后使能p2p（EnableP2p、FormGroup）。
3. 投屏source端发现sink端后，选择并连接，连接上了以后，wfd scene触发连接回调函数（OnP2pConnectionChanged）。
4. wfd scene在回调函数中，发现是连接请求，校验surface map中是否有空余surface，没有直接拒绝接入；对比mac地址，若是新连接，绑定一个surface id加入到source map中，若已存在则不处理。当是新连接时，wfd scene向interaction 发送NOTIFY_AGENT_CREATE。
5. interaction收到消息后向contextmgr发送EVENT_CONTEXTMGR_AGENT_CREATE事件（同步），contextmgr收到事件后构建context，contextId为空则新构建一个context，否则加入已有的context。
6. context构建成功之后时。然后contextmgr再通知context消息EVENT_CONTEXT_AGENT_CREATE，context收到消息后创建sink agent、wfd session。
7. wfd session创建成功后，context向channelmgr发送EVENT_MEDIA_CHANNEL_CREATE（同步）事件，channelmgr收到事件后创建meidachannel。mediachannel创建时，同时创建环形队列。
8. wfd scene 在上面创建成功后，记录对应的context id、agent id到对应的source map中。
9. wfd scene 通过私有消息，发送连接上来设备的ip和连接端口以及绑定的surface id给wfdsession。
10. wfd scene向interaction传递agent启动的消息NOTIFY_AGENT_START，interaction通过context向sink agent转发EVENT_AGENT_START事件。
11. sink agent收到EVENT_AGENT_START事件后控制wfd session进行SESSION_START操作。
12. wfd session 接收到SESSION_START消息后，初始化tcp client，并连接scene私有消息发送过来的ip和端口，等待和source进行M1-M4消息交互。
13. wfd session 第一次收到M4消息后，记录下音视频格式信息。接着发送事件NOTIFY_PROSUMER_CREATE给sink agent，后续仍进行M5-M7的交互。
14. sink agent收到通知后发送事件EVENT_MEDIA_CONSUMER_CREATE给mediachannel。
15. mediachannel收到事件后创建wfd consumer，并进行初始化操作。
16. wfd consumer初始化完成后通知mediachannel，mediachannel回复sink agent EVENT_AGENT_STATE_PROSUMER_CREATE事件。
17. sink agent收到事件后，通知wfd session 状态 STATE_PROSUMER_CREATE_SUCCESS。
18. 然后wfd session 发送私有事件EVENT_VIDEOCHAT_MEDIA_INIT至wfd comsumer（包含前后台显示属性），wfd consumer在收到私有消息后初始化网络udp server端，TS流解封装器，然后consumer发送EVENT_VIDEOCHAT_STATE_MEDIA_INIT事件至receive session。
19. wfd session收到消息后,发送STATE_SESSION_STARTED给sink agent。
20. sink agent收到消息后发送EVENT_MEDIA_CONSUMER_START事件至mediachannel。
21. mediachannel通知wfd consumer开始网络收流StartNetworkServers，收到的数据（根据前后台属性过滤）放到所属mediachannel的环形队列中。
22. consumer开始完成后，通知mediachannel状态PROSUMER_NOTIFY_START_SUCCESS。
23. medichannel收到状态通知后，根据收流类型创建并初始化audio player和video player。
24. 初始化完成后，mediachannel发送消息EVENT_AGENT_STATE_PROSUMER_START给agent。
25. wfd scene 通知interaction设置surface的消息NOTIFY_AGENT_SET_SURFACE，interaction转发事件EVENT_AGENT_CHANNEL_SETSURFACE到对应的sink agent。
26. sink agent收到事件后，转发事件EVENT_MEDIA_CHANNEL_SETSURFACE发送到对应的mediachannel。
27. mediachannel，判断通过后将suface设置给video player中的avcodec，用于解码直接送显使用。
28. 设置完成后，mediachannel发送事件EVENT_AGENT_STATE_CHANNEL_SETSURFACE给agent。
29. agent 发送事件EVENT_INTERACTION_STATE_CHANNEL_SETSURFACE 给interaction。
30. interaction 通知 wfd scene 设置surface成功，wfd scene 通知应用 ConnectionChanged，将source端连接并绑定surface id信息告诉应用。
31. 投屏默认静音，wfd scene发送消息NOTIFY_MEDIA_PLAY_PAUSE(audio)给interaction，然后通过agent转发EVENT_MEDIA_PLAY_PAUSE给mediachannel，mediachannel设置audio pause标识为true。
32. 如果surface的显示属性时后台显示，那wfd scene发送消息NOTIFY_MEDIA_PLAY_GOP给interaction，然后通过agent转发EVENT_MEDIA_PLAY_GOP给mediachannel，mediachannel设置gop play标识为true。
33. wfd scene发送消息NOTIFY_MEDIA_PLAY_START至interaction, interaction收到消息后，则发送EVENT_AGENT_PLAY_START至对应的agent。
34. agent收到消息后再转发事件EVENT_MEDIA_PLAY_START 至对应的mediachannel。
35. mediachannel收到播放请求后，将audio 和 video 的解码播放对象（media player统一管理）挂载到环形队列上，然后开启解码播放线程。
36. 开启完成后mediachannel设置isPlaying_为true，然后发送事件EVENT_AGENT_STATE_MEDIA_PLAYSTART给agent。

### 3.4 sink端断开投屏
#### 业务流程

1. 应用侧通过IPC向框架层发送WfdSinkDisconnected消息，同时传入surfaceId。
2. wfd scene 收到消息后，查询此surfaceId是否以及绑定到一个source上，如果没有就不处理。
3. 如果已经绑定了，wfd scene发送NOTIFY_AGENT_DESTROY消息给interaction，同时传入需要销毁的agentId，interaction通过事件EVENT_CONTEXT_AGENT_DESTROY转发至对应的context。
4. context收到事件后，判断要销毁的是sink agent，且sink agent下没有src agent，context直接转发EVENT_AGENT_DESTROY消息给sink agent。
5. sink agent收到EVENT_AGENT_DESTROY消息后后控制wfd session进行SESSION_STOP操作。
6. wfd session收到消息后发送teardown给投屏source，关闭tcp连接，同时通知sink agent 状态变为STATE_SESSION_STOPED。
7. sink agent 发送消息EVENT_MEDIA_PRODUCER_STOP到mediachannel。
8. mediachannel 在收到sink agent 发来的EVENT_MEDIA_CONSUMER_STOP消息后，会先去停止相关的audio 和 video的解码播放线程，并控制对应的wfd consumer进行PROSUMER_STOP操作。
9. wfd consumer收到PROSUMER_STOP后停止网络收流和TS解封装，完成后通知mediachannel PROSUMER_NOTIFY_STOP_SUCCESS状态。
10. mediachannel收到通知后，接着通知sink agent事件EVENT_AGENT_STATE_PROSUMER_STOP。
11. sink agent收到消息后，通知wfd session destroy，session进行资源Release。
12. wfd session destroy完成后通知sink agent ，sink agent 发送EVENT_MEDIA_PRODUCER_DESTROY消息给mediachannel。
13. mediachanne收到EVENT_MEDIA_PRODUCER_DESTROY后，控制wfd consumer进行PROSUMER_DESTROY操作。
14. wfd consumer 在PROSUMER_DESTROY操作时进行资源 Release，完成后通知mediachannel PROSUMER_NOTIFY_DESTROY_SUCCESS状态。
15. mediachannel收到通知后给sink agent回复事件EVENT_AGENT_STATE_PROSUMER_DESTROY。
16. sink agent 在收到mediachannel回复的后，需要给channelmgr发送EVENT_MEDIA_CHANNEL_DESTROY消息。
17. channelmgr收到EVENT_MEDIA_CHANNEL_DESTROY消息后，删除对应的mediachannel，并且转发EVENT_CONTEXTMGR_STATE_CHANNEL_DESTROY消息给contexmgr。
18. contexmgr收到消息后先发送EVENT_CONTEXT_STATE_AGENT_DESTROY到对应的context，进行agent的删除，同时通知intercation对应的agent 删除事件EVENT_INTERACTION_STATE_AGENT_DESTROY。然后判断对应的contex下面是否已经清空了agent，如果清空了，则删除这个context。
19. intercation收到EVENT_INTERACTION_STATE_AGENT_DESTROY事件后， 通知 wfd scene 删除agent成功，wfd scene 删除对应的source map中的绑定关系，并通知应用 ConnectionChanged，将source端断连并解绑surface id信息告诉应用。

### 3.5 关闭wfd sink端服务
#### 业务流程

1. 应用侧通过IPC向框架层发送WfdSinkStop消息。
2. wfd scene收到消息后disabled p2p，并且置正在停止状态。
3. wfd scene查看绑定关系map，如果有绑定的，循环发送NOTIFY_AGENT_DESTROY消息给interaction，流程参考上面 sink端断开投屏 的操作。
4. wfd scene在后面收到agent 删除的通知后进行解绑操作，并判断绑定关系map是否已经为空，如果为空且状态是正在停止，则置状态为未开始。

### 3.6设置surface前后台显示属性
#### 业务流程

1. 应用侧通过IPC向框架层发送设置surface 显示属性的消息，wfd scene通过surfaceId查看对应的surface显示属性是否有变化，如果没有，直接返回。
2. 如果surface显示属性有变化，则更新对应surface显示属性。
3. 同时查看此surface是否已经绑定了投屏source，没有就返回；如果绑定了，wfd scene根据surfaceId查询绑定的agentId，然后发送NOTIFY_MEDIA_PLAY_GOP(前台换后台)/NOTIFY_MEDIA_PLAY_ALL(后台换前台)给interaction。
4. interaction转发消息EVENT_AGENT_PLAY_GOP/EVENT_AGENT_PLAY_ALL给agent。
5. agent转发消息EVENT_MEDIA_PLAY_GOP/EVENT_MEDIA_PLAY_ALL给mediachannel。
6. mediachannel根据消息设置gop play =  ture/false。

## 4 框架内部统一错误提示流程
#### 非阻塞式提示OnInfo
接口执行过程或内部运行过程触发的状态信息或错误信息的通知，应用可根据需要进行处理。框架内部资源不会释放。
#### 内部错误提示OnError
接口执行过程或内部运行过程触发的关键性错误通知，此时框架内部资源会释放或进入错误状态，等待被删除。
