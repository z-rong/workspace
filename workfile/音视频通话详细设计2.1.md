## 1 需求背景
### 1.1 应用需求
![](https://cdn.nlark.com/yuque/0/2023/jpeg/32611479/1677840011467-8f8b4e95-0a7d-4b88-adb1-dc4da495358c.jpeg)
应用通过分布式硬件框架，可以在局域网内发现设备列表，并获取对应设备的IP；
IM主叫能力支持：发起呼叫、取消呼叫、挂断通话、开关麦克风、开关摄像头；
IM被叫能力支持：接听呼叫、拒绝接听、挂断通话、开关麦克风、开关摄像头；
应用可设置对端显示和本地回显的窗口，并把窗口的surface设置给音视频通话服务进行画面输出。
### 1.2 业务流程
#### 1.2.1 呼叫接听流程
##### 业务流程
![](https://cdn.nlark.com/yuque/0/2023/jpeg/32611479/1677839656157-a4bed967-883a-4bd4-a151-84bfc7c38d5f.jpeg)

1. 主叫端通过分布式能力发现局域网内的可进行音视频通话的设备列表。
2. 主叫端选择列表中的一个设备发起呼叫时，首先进行本地音视频初始化。
3. 主叫端调用CreateReceiver接口，创建本地接收对端的代理，创建成功后记录下端口，接着调用SetSurface接口为此Receiver视频源设置播放窗口，然后调用StartPlay接口。
4. 主叫端接着调用CreateCapture接口，创建本地音视频采集相关资源，创建成功后，接着调用SetSurface接口为本地采集视频源设置回显窗口，然后调用StartPlay接口。
5. 主叫本地音视频初始化完成后，通过应用消息发送呼叫请求给被叫端（带上CreateReceiver接口返回的收流端口）
6. 被叫端收到应用的呼叫请求后，选择接听呼叫，同时进行本地音视频的初始化。
7. 被叫端调用CreateReceiver接口，创建本地接收对端的代理，创建成功后记录下端口，接着调用SetSurface接口为此Receiver视频源设置播放窗口，然后调用StartPlay接口。
8. 被叫端接着调用CreateCapture接口，创建本地音视频采集相关资源，CreateCapture调用成功后，着调用SetSurface接口为此Receiver视频源设置播放窗口，然后调用StartPlay接口。
9. 被叫端完成本地的音视频初始化后，调用AddDevice接口（参数是主叫端发送呼叫的请求中带过来的主叫端收流地址和端口）给主叫端发送被叫端的音视频。
10. 被叫端AddDevice完成后，通过应用消息应答主叫端的呼叫请求，并带上被叫端调用CreateReceiver生成的接收端口。
11. 主叫端接收到呼叫应答消息后，进入通话接听成功状态，同时调用AddDevice接口（参数是被叫端的接收端口）向被叫端发送音视频流。

![](https://cdn.nlark.com/yuque/0/2023/jpeg/32611479/1677841782189-a18e7ab4-e1b5-41f1-87a6-ed44045c8bd2.jpeg)
#### 1.2.2 挂断取消流程
##### 业务流程
![](https://cdn.nlark.com/yuque/0/2023/jpeg/32611479/1677840976074-3714f1f4-9894-4f78-840f-5e185f568bc1.jpeg)

1. 主叫进行取消、挂断操作，或被叫进行拒接、挂断操作，通过应用消息发送操作消息给对端。
2. 主叫或被叫端调用StopPlay停止本地和远端的窗口播放。
3. 主被叫端调用完StopPlay接口后，调用DestroyCapture和DestroyReceiver接口，删除本地和远端的音视频资源，流程结束。

## 2 框架模型结构
![](https://cdn.nlark.com/yuque/0/2023/jpeg/32611479/1677842754127-011d0eeb-83cc-4763-8e22-39a6b689329f.jpeg)

1. 一个context与可以包含多个sinkagent和srcagent，一个srcagent一定归属于一个sinkagent。
2. 一个sinkagent对应一个consumer，一个srcagent对应一个producer。
3. 一个mediachannel只包含一个consumer，但包含多个producer。
4. 一个mediachannel对应一个环形队列，环形队列用于缓存consumer提供的编码后的媒体数据，此mediachannel中的produer以被动模式注册到此环形队列，当被通知有数据进入环形队列时，去队列取数据进行网络发送。
5. 一个mediachannel对应一个playcontroller，此播放器以被动模式从环形队列获取音视频编码数据，封装了audioplayer和videoplayer。audioplayer用于将音频数据解码成pcm并进行音频播放；videoplayer主要通过avcodec将视频编码数据解码成yuv并直接进行送显，显示用的surface由外部应用调用接口来设定。

## 3 框架接口流程
### 3.1 创建接收端Receiver
#### 业务流程

1. 应用侧通过IPC向框架层发送创建接收端receiver的消息，scene通过交互模块interaction传递receiver创建事件。
2. interaction向contextmgr发送EVENT_CONTEXTMGR_AGENT_CREATE事件（同步），contextmgr收到事件后构建context，contextId为空则新构建一个context，否则加入已有的context。
3. context构建成功之后时。然后contextmgr再通知context消息EVENT_CONTEXT_AGENT_CREATE，context收到消息后创建sink agent、receive session。
4. session创建成功后，context向channelmgr发送EVENT_MEDIA_CHANNEL_CREATE（同步）事件，channelmgr收到事件后创建meidachannel。mediachannel创建时，同时创建环形队列。
5. scene向interaction传递agent启动的消息，interaction通过context向sink agent转发EVENT_AGENT_START事件。
6. sink agent收到EVENT_AGENT_START事件后控制receive session进行SESSION_START操作。
7. receive session收到消息后通知sink agent（NOTIFY_PROSUMER_CREATE）。
8. sink agent收到通知后发送事件EVENT_MEDIA_CONSUMER_CREATE给mediachannel。
9. mediachannel收到事件后创建rtp consumer，并进行初始化操作。
10. rtp consumer初始化完成后通知mediachannel，mediachannel回复sink agent EVENT_AGENT_STATE_PROSUMER_CREATE事件。
11. sink agent收到事件后，通知reveive session 状态 STATE_PROSUMER_CREATE_SUCCESS。
12. 然后rtpsession 发送私有事件EVENT_VIDEOCHAT_MEDIA_INIT至rtp comsumer，rtp consumer在收到私有消息后初始化网络udp server端，然后consumer发送EVENT_VIDEOCHAT_STATE_MEDIA_INIT事件至receive session。
13. reveive session收到消息后,发送STATE_SESSION_STARTED给sink agent。
14. sink agent收到消息后发送EVENT_MEDIA_CONSUMER_START事件至mediachannel。
15. mediachannel通知rtp consumer开始网络收流StartNetworkServers，收到的数据放到所属mediachannel的环形队列中。
16. consumer开始完成后，通知mediachannel状态PROSUMER_NOTIFY_START_SUCCESS。
17. medichannel收到状态通知后，根据收流类型创建并初始化audio player和video player。
18. 初始化完成后，mediachannel发送消息EVENT_AGENT_STATE_PROSUMER_START给agent。

### 3.2 创建采集端Capture
#### 业务流程

1. 应用侧通过IPC向框架层发送创建采集端Capture的消息，scene通过交互模块interaction传递capture创建事件。
2. interaction向contextmgr发送EVENT_CONTEXTMGR_AGENT_CREATE事件（同步），contextmgr收到事件后构建context，contextId为空则新构建一个context，否则加入已有的context。
3. context构建成功之后时。然后contextmgr再通知context消息EVENT_CONTEXT_AGENT_CREATE，context收到消息后创建sink agent、capture session。
4. session创建成功后，context向channelmgr发送EVENT_MEDIA_CHANNEL_CREATE（同步）事件，channelmgr收到事件后创建meidachannel。mediachannel创建时，同时创建环形队列。
5. scene向interaction传递agent启动的消息，interaction通过context向sink agent转发EVENT_AGENT_START事件。
6. sink agent收到EVENT_AGENT_START事件后控制capture session进行SESSION_START操作。
7. capture session根据captureType对麦克风和相机进行检测，检查可用后通知sink agent（NOTIFY_PROSUMER_CREATE）。
8. sink agent收到通知后发送事件EVENT_MEDIA_CONSUMER_CREATE给mediachannel。
9. mediachannel收到事件后创建capture consumer，并进行初始化操作。
10. capture consumer初始化完成后通知mediachannel，mediachannel回复sink agent EVENT_AGENT_STATE_PROSUMER_CREATE事件。
11. sink agent收到事件后，通知capture session 状态 STATE_PROSUMER_CREATE_SUCCESS。
12. 然后capture session 发送私有事件EVENT_VIDEOCHAT_MEDIA_INIT至capture comsumer，consumer根据captureType进行音频采集编码器和视频采集的初始化，然后consumer发送EVENT_VIDEOCHAT_STATE_MEDIA_INIT事件至capture session。
13. capture session收到消息后,发送STATE_SESSION_STARTED给sink agent。
14. sink agent收到消息后发送EVENT_MEDIA_CONSUMER_START事件至mediachannel。
15. mediachannel通知capture consumer开始采集StartCapture，采集后的数据放到所属mediachannel的环形队列中。
16. consumer开始完成后，通知mediachannel状态PROSUMER_NOTIFY_START_SUCCESS。
17. medichannel收到状态通知后，根据采集类型创建并初始化audio player和video player。
18. 初始化完成后，mediachannel发送消息EVENT_AGENT_STATE_PROSUMER_START给agent。

### 3.3 添加设备Device
#### 业务流程

1. 应用侧通过IPC向框架层发送添加设备的消息，scene通过交互模块interaction传递AddDevice创建事件。
2. interaction向contextmgr发送EVENT_CONTEXTMGR_AGENT_CREATE事件（同步），contextmgr收到事件后根据传入的contextId，给对应的contex转发EVENT_CONTEXT_AGENT_CREATE消息。
3. context收到消息后创建src agent、send session，并将src agent绑定到对应的sink agent下，更新从sink agent获取的对应mediachannelId。
4. scene向上面创建的send session发送私有事件EVENT_SESSION_INIT，记录要添加设备的ip和port。
5. scene向interaction传递agent启动的消息，interaction通过context向src agent转发EVENT_AGENT_START事件。
6. src agent收到EVENT_AGENT_START事件后控制send session进行SESSION_START操作。
7. send session处理完SESSION_START，通知src agent（NOTIFY_PROSUMER_CREATE）。
8. src agent收到通知后发送事件EVENT_MEDIA_PRODUCER_CREATE给mediachannel。
9. mediachannel收到事件后创建rtp producer，放入到producer列表中，并进行初始化操作。
10. rtp producer初始化完成后通知mediachannel，mediachannel回复src agent EVENT_AGENT_STATE_PROSUMER_CREATE事件。
11. src agent收到事件后，通知send session 状态 STATE_PROSUMER_CREATE_SUCCESS。
12. 然后send session 发送私有事件EVENT_VIDEOCHAT_MEDIA_INIT至rtp producer，producer根据ip和port初始化udp发送客户端，然后producer发送EVENT_VIDEOCHAT_STATE_MEDIA_INIT事件至send session。
13. send session收到消息后,发送STATE_SESSION_STARTED给src agent。
14. src agent收到消息后发送EVENT_MEDIA_PRODUCER_START事件至mediachannel。
15. mediachannel将rtp producer挂载到环形队列，并通知rtp producer开始发送。
16. rtp producer开始完成后，通知mediachannel状态PROSUMER_NOTIFY_START_SUCCESS。
17. medichannel收到状态通知后，mediachannel发送消息EVENT_AGENT_STATE_PROSUMER_START给src agent。

### 3.4 设置视频源解码播放的窗口显示SetSurface
#### 业务流程

1. 应用侧通过IPC向框架层发送SetSurface的消息，同时传入对应的contextId，agnetId，和surface对象，通过interaction以及事件中心调度中心，将事件EVENT_AGENT_CHANNEL_SETSURFACE发送到对应的sink agent。
2. sink agent收到事件后，转发事件EVENT_MEDIA_CHANNEL_SETSURFACE发送到对应的mediachannel。
3. mediachannel收到消息后，判断如果正在播放或者不包含视频源，直接通过EVENT_AGENT_PROSUMER_INFO通知agent设置错误，由agent转发EVENT_INTERACTION_MSG_INFO消息给interaction，再转给scene，通过OnInnerInfo转发给应用。
4. mediachannel，判断通过后将suface设置给video player中的avcodec，用于解码直接送显使用。
5. 设置完成后，mediachannel发送事件EVENT_AGENT_STATE_CHANNEL_SETSURFACE给agent。

### 3.5 启动播放StartPlay
#### 业务流程

1. 应用侧通过IPC向框架层发送启动播放的消息，同时传入对应的contextId和agentId，scene根据agentId是否有效，发送消息至interaction, interaction收到消息后，则发送EVENT_AGENT_PLAY_START至对应的agent。
2. agent收到消息后再转发事件EVENT_MEDIA_PLAY_START 至对应的mediachannel。
3. mediachannel收到播放请求后，检查是否已经开启播放，已经开启则使用oninfo提示agent重复开始，否则继续。
4. 接着检查video部分，如果具备video，但没有SetSurface，直接使用oninfo提示agent开始失败，否则继续。
5. 检查完成后将audio 和 video 的解码播放对象（media player统一管理）挂载到环形队列上，然后开启解码播放线程。
6. 开启完成后mediachannel设置isPlaying_为true，然后发送事件EVENT_AGENT_STATE_MEDIA_PLAYSTART给agent。

### 3.6 停止播放StopPlay
#### 业务流程

1. 应用侧通过IPC向框架层发送启动播放的消息，同时传入对应的contextId和agentId，scene根据agentId是否有效，发送消息至interaction, interaction收到消息后，则发送EVENT_AGENT_PLAY_STOP至对应的agent。
2. agent收到消息后再转发事件EVENT_MEDIA_PLAY_STOP 至对应的mediachannel。
3. mediachannel收到停止播放请求后，首先将audio 和 video 的解码播放对象（media player统一管理）从环形队列上脱离，然后停止解码播放线程。
4. 停止完成后mediachannel设置isPlaying_为false，接着发送事件EVENT_AGENT_STATE_MEDIA_PLAYSTOP给agent。

### 3.7暂停采集PauseCapture
#### 业务流程

1. 应用侧通过IPC向框架层发送添加设备的消息，scene通过交互模块interaction发送EVENT_AGENT_PAUSE事件给sink agent
2. sink agent收到事件后，通知send session更新状态为SESSION_PAUSE，并且带入暂停采集的类型参数

4. sink agent收到session的状态通知后，发送EVENT_MEDIA_CONSUMER_PAUSE事件给对应的capture consumer。
5. capture consumer暂停成功后，通知mediachannel状态PROSUMER_NOTIFY_PAUSE_SUCCESS。
6. mediachannel收到状态通知后，发送EVENT_AGENT_STATE_PROSUMER_PAUSE事件给sink agent。

### 3.9 销毁Destroy
DestoryCapture和DestoryReveiver在流程上是一致的，以DestoryCapture举例。
#### 业务流程

1. 应用侧通过IPC向框架层发送DestoryCapture消息，同时传入需要销毁的agentId，interaction通过事件EVENT_CONTEXT_AGENT_DESTROY转发至对应的context。
2. context收到事件后，判断要销毁的是sink agent，需要设置destory_为true，并且检查此sink agent下是否包含src agent。
3. 如果sink agent下没有src agent，context直接转发EVENT_AGENT_DESTROY消息给sink agent，如果存在src agent，则循环转发EVENT_AGENT_DESTROY给src agent。
4. src agent收到EVENT_AGENT_DESTROY消息后后控制send session进行SESSION_STOP操作。
5. send session操作完成后通知src agent 状态变为STATE_SESSION_STOPED。
6. src agent 发送消息EVENT_MEDIA_PRODUCER_STOP到mediachannel。
7. mediachannel收到消息后从producer队列中找出对应的producer，从环形队列去挂载，并且控制producer进行PROSUMER_STOP操作。
8. producer进行stop操作，停止udp客户端发送线程，关闭网络连接，并通知mediachannel状态PROSUMER_NOTIFY_STOP_SUCCESS。
9. mediachannel收到后发送EVENT_AGENT_STATE_PROSUMER_STOP给src agent应答。
10. src agent收到后告诉send session 消息STATE_PROSUMER_STOP_SUCCESS，并控制session进行SESSION_DESTROY操作。
11. send session操作完成后通知src agent 状态变为STATE_SESSION_DESTROYED。
12. src agent 发送消息EVENT_MEDIA_PRODUCER_DESTROY给mediachannel进行删除。
13. mediachanne收到EVENT_MEDIA_PRODUCER_DESTROY后，从producer的列表中找到此rtp producer，并控制它进行PROSUMER_DESTROY操作。
14. rtp producer 在PROSUMER_DESTROY操作时进行资源 Release，完成后通知mediachannel PROSUMER_NOTIFY_DESTROY_SUCCESS状态。
15. mediachannel收到通知后从producers列表中删除此rtp producer，接着通知src agent事件EVENT_AGENT_STATE_PROSUMER_DESTROY。
16. agent 收到EVENT_AGENT_STATE_PROSUMER_DESTROY事件后，判断是src agent处理，则发送事件EVENT_CONTEXT_STATE_AGENT_DESTROY给context。
17. context收到消息，删除此src agent，并判断此src agent对应的sink agent是否需要删除（src agent列表为空，destory_标识为true）。同时context给interaction发送EVENT_INTERACTION_STATE_AGENT_DESTROYED，告知interaction删除此src agent。
18. 如果sink agent需要删除，context转发EVENT_AGENT_DESTROY给对应的sink agent。
19. sink agent收到消息EVENT_AGENT_DESTROY后，和src agent 流程基本一致，也是先stop，然后再destory。
20. mediachannel 在收到sink agent 发来的EVENT_MEDIA_CONSUMER_STOP消息后，会先去停止相关的audio 和 video的解码播放线程。
21. sink agent 在收到mediachannel回复的EVENT_AGENT_STATE_PROSUMER_DESTROY后，需要给channelmgr发送EVENT_MEDIA_CHANNEL_DESTROY消息。
22. channelmgr收到EVENT_MEDIA_CHANNEL_DESTROY消息后，删除对应的mediachannel，并且转发EVENT_CONTEXTMGR_STATE_CHANNEL_DESTROY消息给contexmgr。
23. contexmgr收到消息后先发送EVENT_CONTEXT_STATE_AGENT_DESTROY到对应的context，进行agent的删除，然后判断对应的contex下面是否已经清空了agent，如果清空了，则删除这个context。

## 4 框架内部统一错误提示流程
#### 非阻塞式提示OnInfo
接口执行过程或内部运行过程触发的状态信息或错误信息的通知，应用可根据需要进行处理。框架内部资源不会释放。
#### 内部错误提示OnError
接口执行过程或内部运行过程触发的关键性错误通知，此时框架内部资源会释放或进入错误状态，等待被删除。
