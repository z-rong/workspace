## 1、编译测试用例

单元测试默认只生成ninja文件，不进行编译，需要使用编译命令进行手动编译

```
// 编译所有单元测试用例
./build.sh --product-name khdvk_rk3568_a --build-target make_test

// 编译指定组件测试用例
./build.sh --product-name khdvk_rk3568_a --build-target sharing_framework_test
或
ninja -C out/khdvk_rk3568_a sharing_framework_test
```

测试组件名称通常是：组件名_test

例如投播框架的组件名叫sharing_framework，测试名称就叫sharing_framework_test；音视频流转组件名叫dfs_media_service，测试名称就叫做dfs_media_service_test

组件名可以在bundle.json文件中查看

## 2、执行测试

### 本地执行

window平台需要修改`/test/testfwk/developer_test/config/user_config.xml`文件，testcase需要改成false，dir中加入单元编译生成的路径，单元测试生成路径为`\out\khdvk_rk3568_a\tests\`，修改完成后执行`/test/testfwk/developer_test/`目录下的`start.bat`脚本

```
<!-- whether compile test case, default false -->
    <testcase>false</testcase>
...
  <!-- configure test cases path -->
  <test_cases>
    <dir>G:\future3.2\out\khdvk_rk3568_a\tests\</dir>
  </test_cases>
```



linux平台无需操作，直接执行`/test/testfwk/developer_test/`目录下的`start.sh`脚本



执行脚本之后选择`system_arm_default`产品类型，然后选择执行`\out\khdvk_rk3568_a\tests\unittest`中的测试模块

```
run -t UT -tp sharing_framework
```

## 3、覆盖率测试

本地执行：

1、 先在测试的模块gn文件中添加编译选项

```
  cflags_cc = ["--coverage"]
  ldflags = [ "--coverage" ]
```

添加这个选项之后编译会同时生成桩文件，桩文件会记录编译模块中所有的函数、可执行代码。

2、添加参数执行单元测试

```
run -t UT -ts test_remote_schedule_service -cov coverage
```

执行完之后会在设备中生成/data/test/home
