

## 媒体库

### 1、基础功能

MediaLibrary 的功能支持扫描设备中所有媒体文件的能力，为相册、音视频播放器、文件管理器等应用提供统一的媒体元数据信息操作接口，目前可实现的具体能力如下：

● 查询音频、视频和图片文件元数据信息

● 查询图片和视频相册

● 媒体文件操作如创建、重命名、拷贝和删除

● 相册操作如创建、重命名和删除

### 2、4.0升级对比

媒体库4.0升级代码实现上的修改如下：

- 原有仓[**multimedia_medialibrary_standard**](https://gitee.com/openharmony/multimedia_medialibrary_standard)废弃，改用新仓[**multimedia_media_library**](https://gitee.com/openharmony/multimedia_media_library)
- 媒体库**ohos.multimedia.medialibrary**接口从version9开始废弃，由相机管理**ohos.file.photoAccessHelper(相册管理模块)**接口代替
- 媒体库从3.2开始去掉了IPC调用机制，不再有medialibrary_service，移除了媒体扫描动态应用

> 在API version 10上，摒弃了物理目录作为相册的设计，采用了逻辑相册的设计，一个相册中可以添加多个文件，一个文件也可以在多个相册中呈现。新的设计将带来parent、albumId、albumUri和albumName属性使用上的不兼容，无法作为MediaFetchOptions的参数在getFileAssets接口中使用。请参考[changelogs-mediaLibrary.md](https://gitee.com/openharmony/docs/blob/master/zh-cn/release-notes/changelogs/OpenHarmony_4.0.8.2/changelogs-mediaLibrary.md)。

### 4、对外接口

媒体库对外接口较多，主要接口是对资源文件和相册的操作，其次是文件和相册的属性操作，这里列举主要接口

- getPublicDirectory 查看公共目录

根据参数传递的目录类型返回不同类型媒体库的相对目录。例如："Cameras/"、"Videos/"、"Pictures/"、"Audios/"、"Documents/"和"Downloads/".

- getFileAssets 获取文件资源

调用DataShareHelper的Query查询接口，获取文件资源，最终调用JsDataShareExtAbility的Query接口实现。

- getAlbums 获取相册

查询媒体中的相册目录信息。

- createAsset 创建资源

调用DataShareHelper提供的Insert()接口插入数据库，传入的uri通过“create_asset”字符表示创建数据资源。

- deleteAsset 删除资源

调用DataShareHelper提供的Insert()接口插入数据库，传入的uri通过“delete_asset”字符表示删除数据资源。

- open打开文件

通过获取到的FileAsset，调用FileAsset属性方法open获取文件描述符

- close关闭文件

通过获取到的FileAsset以及获取到的文件描述符，调用FileAsset属性方法close关闭文件，并将文件信息记录到数据库

媒体库流程大致都是通过分布式数据库对象DataShareHelper操作媒体库数据库，媒体库操作的数据在/data/app/el2/100/database/com.ohos.medialibrary.medialibrarydata/media_library.db目录下。这是SQLite3数据库的文件，可以使用SqliteManager软件打开

### 5、兼容性影响

**getFileAssets接口获取文件资源兼容性影响：**

api10采用了逻辑目录作为相册的设计，新设计会带来parent、albumId、albumUri和albumName属性使用上的不兼容，无法作为MediaFetchOptions的参数在getFileAssets接口中使用。

错误示例

```
import mediaLibrary from '@ohos.multimedia.mediaLibrary';

async function example() {
  try {
    let context = getContext(this);
    let media = mediaLibrary.getMediaLibrary(context);
    let fileKeyObj = mediaLibrary.FileKey;
    let albumId = 1;
    let getImageOp = {
      selections: fileKeyObj.ALBUM_ID + '= ?', // 使用parent、albumId、albumUri和albumName属性查询均无法获取文件资源。
      selectionArgs: [albumId.toString()],
    };
    const fetchFileResult = await media.getFileAssets(getImageOp); // 查询失败，获取的fetchFileResult为空。
    const fileAsset = await fetchFileResult.getFirstObject();
    console.info('mediaLibrary fileAsset displayName: ' + fileAsset.displayName);
  } catch (err) {
    console.error('mediaLibrary fail, err: ' + err);
  }
}
```

正确示例

```
import mediaLibrary from '@ohos.multimedia.mediaLibrary';

async function example() {
  try {
    let context = getContext(this);
    let media = mediaLibrary.getMediaLibrary(context);
    let fileKeyObj = mediaLibrary.FileKey;
    let imageType = mediaLibrary.MediaType.IMAGE;
    let getImageOp = {
      selections: fileKeyObj.MEDIA_TYPE + '= ?',
      selectionArgs: [imageType.toString()],  // 查询所有图片类型的文件。
    };
    const fetchFileResult = await media.getFileAssets(getImageOp); 
    const fileAsset = await fetchFileResult.getFirstObject();
    console.info('mediaLibrary fileAsset displayName: ' + fileAsset.displayName);
  } catch (err) {
    console.error('mediaLibrary fail, err: ' + err);
  }
}
```

**getAlbums接口获取相册兼容性影响：**

由于API version 10的SDK上relativePath和相册没有关联关系，在使用getAlbums时不支持relativePath作为查询条件，并且ALBUM_NAME参数只能使用"Camera"和"Screenshots"。

错误示例

```
import mediaLibrary from '@ohos.multimedia.mediaLibrary';

async function example() {
  try {
    let context = getContext(this);
    let media = mediaLibrary.getMediaLibrary(context);
    let AlbumNoArgsfetchOp = {
      selections: mediaLibrary.FileKey.ALBUM_NAME + ' = ?',
      selectionArgs: ['新建相册1'], // 获取albumName为新建相册1的相册。
    };
    const albumList = await media.getAlbums(AlbumNoArgsfetchOp); // 查询失败，获取的fetchFileResult为空。
    for (let i = 0; i < albumList.length; i++) {
      console.info('mediaLibrary album albumName: ' + albumList[i].albumName);
    }
  } catch (err) {
    console.error('mediaLibrary fail, err: ' + err);
  }
}
```

**正确示例：**

```
import mediaLibrary from '@ohos.multimedia.mediaLibrary';

async function example() {
  try {
    let context = getContext(this);
    let media = mediaLibrary.getMediaLibrary(context);
    let AlbumNoArgsfetchOp = {
      selections: mediaLibrary.FileKey.ALBUM_NAME + ' = ? OR ' + mediaLibrary.FileKey.ALBUM_NAME + ' = ?',
      selectionArgs: ['Camera', 'Screenshots'], // 获取相机相册和截屏录屏相册。
    };
    const albumList = await media.getAlbums(AlbumNoArgsfetchOp);
    for (let i = 0; i < albumList.length; i++) {
      console.info('mediaLibrary album albumName: ' + albumList[i].albumName);
    }
  } catch (err) {
    console.error('mediaLibrary fail, err: ' + err);
  }
}
```



#### ps

媒体库和图库存在较多的关联，媒体库主要负责获取媒体文件信息，无法对文件内容进行操作。图库则是无法获取文件信息，但是可以对获取到的文件进行剪切、旋转、编码等操作。

## 图库

### 1、基础功能

图库对应的功能是提供图片处理，通过一系列简单易用的接口，向用户提供图片源和位图管理能力，目前只支持标准系统设备使用。

- 创建、释放位图。
- 读写像素。
- 获取位图信息。
- 创建、释放图片源。
- 获取图片源信息。
- 创建、释放packer实例。

### 3、对外接口

#### 图库主要通过以下几个类的接口进行操作

-  PixelMap 图像像素类，用于读取或写入图像数据以及获取图像信息
- ImageSource 图片源类，用于获取图片相关信息。
- ImagePacker 图片打包器类，用于图片压缩和打包。
- ImageReceiver 图像接收类，用于获取组件surface id，接收最新的图片和读取下一张图片，以及释放ImageReceiver实例。
- ImageCreator 图像创建模块，用于请求图像原生数据区域，并开放给应用编译原生图像数据的能力。
- image 提供基本的图像操作，包括获取图像信息、读写图像数据。



#### 图库操作流程

![Image development process](images/image-development-process.png)

图库操作时序

1. 以流的形式读取文件
2. 通过读取到的流创建imageSource、PixelMap
3. 通过设置decodeOpts操作图片，比如选择、裁剪等操作
4. 应用将新的PixelMap通过ImagePacker写入文件



![image-20240120213747635](images/image-20240120213747635.png)

使用示例：

```
    // 图片裁剪和旋转
    /**
    * @tc.steps: step1. create jpg image source by istream source stream and default format hit
    * @tc.expected: step1. create jpg image source success.
    */
    std::unique_ptr<std::fstream> fs = std::make_unique<std::fstream>();
    fs->open("/data/local/tmp/image/test.jpg", std::fstream::binary | std::fstream::in);
    bool isOpen = fs->is_open();
    ASSERT_EQ(isOpen, true);
    uint32_t errorCode = 0;
    SourceOptions opts;
    std::unique_ptr<ImageSource> imageSource = ImageSource::CreateImageSource(std::move(fs), opts, errorCode);
    ASSERT_EQ(errorCode, SUCCESS);
    ASSERT_NE(imageSource.get(), nullptr);
    /**
    * @tc.steps: step2. crop jpg image source to pixel map crop options
    * @tc.expected: step2. crop jpg image source to pixel map success.
    */
    DecodeOptions decodeOpts;
    decodeOpts.CropRect.top = 3;
    decodeOpts.CropRect.width = 100;
    decodeOpts.CropRect.left = 3;
    decodeOpts.CropRect.height = 200;
    decodeOpts.desiredSize.width = 200;
    decodeOpts.desiredSize.height = 400;
    decodeOpts.rotateDegrees = 90;
    std::unique_ptr<PixelMap> pixelMap = imageSource->CreatePixelMap(decodeOpts, errorCode);
    HiLog::Debug(LABEL_TEST, "create pixel map error code=%{public}u.", errorCode);
    ASSERT_EQ(errorCode, SUCCESS);
    ASSERT_NE(pixelMap.get(), nullptr);
    EXPECT_EQ(200, pixelMap->GetWidth());
    EXPECT_EQ(400, pixelMap->GetHeight());

    ImageInfo imageInfo;
    pixelMap->GetImageInfo(imageInfo);
    // decodeOpts.CropRect = { imageInfo.size.width - 100, imageInfo.size.height - 100, 100, 100 };
    std::unique_ptr<PixelMap> cropPixelMap = imageSource->CreatePixelMap(decodeOpts, errorCode);
    ASSERT_NE(pixelMap.get(), nullptr);
    cropPixelMap->GetImageInfo(imageInfo);

    /**
    * @tc.steps: step3. compress the pixel map to jpeg file.
    * @tc.expected: step3. pack pixel map success and the jpeg compress file size equals to JPEG_PACK_SIZE.
    */
    ImagePacker imagePacker;
    int64_t packSize = OHOS::ImageSourceUtil::PackImage(IMAGE_OUTPUT_JPEG_BUFFER_PATH, std::move(cropPixelMap));
```
